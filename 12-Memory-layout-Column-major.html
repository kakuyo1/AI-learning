转置后若按「新的行」依次访问：a → d → b → e → c → f，内存地址变成 0,3,1,4,2,5，跳跃访问，容易 cache miss。
会不会造成明显的 cache miss？
会。尤其在大矩阵、按「逻辑行」顺序遍历刚转置过的张量时。

CPU 一次会拉一整条 cache line（常见 64 字节）。连续访问时命中率高；跨 stride 跳跃访问时，每读一个数可能都要重新填 cache line，带宽浪费、延迟上升。

主流框架怎么解决？

手段 做法 代价
.contiguous() / .copy() 真正把数据按当前 shape 重新排成连续内存 一次拷贝，之后访问变快
.reshape() 代替 .view() 非连续时自动处理（可能隐式拷贝） 比 view 安全，可能多一次拷贝
算子融合 / 专用 kernel cuBLAS、cuDNN、FlashAttention 等按实际 stride 写高效实现，不一定要求连续 实现复杂，但用户无感
尽量少转置、晚转置 网络设计时保持 NCHW 等原生布局，减少 permute 需要一点设计意识
channels_last 等内存格式 PyTorch 提供可选内存格式，匹配卷积等算子的最优访问模式 显式转换一次

实践建议

• 转置 / permute 之后如果马上有大量逐行计算，先 .contiguous()
• 能不转置就不转置；必须转时，考虑是否可以改成在连续布局下改索引
• 看性能时用 profiler，确认是不是被 non-contiguous 访问拖慢
